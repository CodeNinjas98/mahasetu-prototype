Overview

Secure Government Digital Interoperability Platform — "Connect once. Share securely. Deliver seamlessly."

MahaSetu is not another portal citizens visit. It's an invisible layer that lets existing systems like MahaDBT request verified data from other departments — the citizen never leaves MahaDBT.

Architecture

MahaSetu is invisible to the citizen — it mediates between systems, it doesn't replace them.

Citizen
↓
Legacy Portal (MahaDBT)
"Fetch Verified Income"
↓
API Gateway
↓
Interoperability Core
consent · MDM · policy · canonical · workflow · events · audit
↓
MahaDBT · DB1
Aaple Sarkar · DB2
MahaSwayam · DB3

↓
MahaSetu · DB4

DB1, DB2 and DB3 remain independently owned and isolated. DB4 stores interoperability metadata, consent, audit, events and platform state — not a replacement for departmental databases.

MahaSetu does

Mediate API calls · enforce consent · normalize data · resolve identities · log every event

MahaSetu does not

Replace portals · directly expose databases · merge departmental data · bypass consent
